# Sion review (k3)

Audit of `main` @ 4194729 (Sion 0.2.0). Scope: bugs, perf, missing features,
visuals, UX, aesthetics, delight. Each entry has a confidence tag for
implementation readiness.

Note: open PR #19 (`fix/editor-interactions`) already covers 8-way resize,
rotation controls, zoom controls, persistent creation tools, anchor editing,
and palette detach/close fixes. Entries overlapping it are marked **[PR19]**
and should be re-checked after it lands.

---

## 1. Bugs

### B1. Rotated elements are hit-tested and resized unrotated — [PR19-adjacent]
`SionEditorController.element(at:)` and `connectableElement(at:)` test the
axis-aligned frame, ignoring `rotationRadians`. `resizeCorner(at:frame:)`,
`resizePoint`, `drawSelection`, and `resizedFrame` in `SionCanvasView` also
ignore rotation: handles sit on the unrotated rect and resizing a rotated
element jumps. Magnet editing unrotates the point correctly, so the precedent
exists.
Confidence: high. (Verify against PR #19's rotation work first.)

### B2. SVG export does not wrap text, canvas does
`SionCanvasView.drawText` wraps to the frame width via AppKit; SVG
`renderText` splits only on `\n`. Long shape labels overflow the shape in the
exported SVG / recovery kit. Fidelity gap in a format whose stated goal is
faithful recovery.
Confidence: high (approximate wrap heuristic; exact metrics need AppKit).

### B3. `.overlay` blend mode silently renders as normal
`compositingOperation` maps `.overlay` to `.sourceOver`. Either implement
overlay via `CGContext.setBlendMode` (AppKit has no compositing op for it) or
drop it from the model/exporter. Silent wrongness is worse than absence.
Confidence: high.

### B4. Grid `subdivisions` is modelled and validated but never rendered
`CanvasGrid.subdivisions` (default 1, validated 1...1024) has no effect in
`drawGrid`. Either render major/minor lines or remove the field.
Confidence: high.

### B5. Grid density collapses at low zoom
`drawGrid` clamps spacing to `minimumGridSpacing = 4` in *model* units. At
0.1x zoom that is 0.4 pt on screen: thousands of lines, a solid gray field,
and a slow draw. Clamp in view units (spacing × magnification) and fade/hide
below a readable pitch.
Confidence: high.

### B6. Text is drawn twice while editing
During inline editing the canvas keeps drawing the element's live-updating
text *under* the NSTextView, which renders the same string on top. Any
sub-pixel mismatch shows as doubled/bold text. Skip `drawText` for
`editedElementID` while the editor is open.
Confidence: high.

### B7. Undo mid-drag leaves the view's drag state dangling
`undoSceneEdit` cancels the editor's pending gesture, but `SionCanvasView.drag`
stays non-nil; subsequent drag events throw inside `try?` until mouse-up.
Surfaces as "undo during a drag does nothing visible until mouse-up, then
jumps". Clear the view drag when an external undo/redo lands.
Confidence: high.

### B8. Transient inspector popover fights the color panel
The inspector popover is `.transient`. Clicking a color well opens the shared
color panel; the popover can close on focus loss, discarding context. Use
`.semitransient` (or `.applicationDefined`) for the inspector.
Confidence: medium (verify behavior on-device).

### B9. Window title never reflects the file
`SionDocumentWindowController.init` sets `window.title` once from
`document.title` ("Untitled"). After Save As the archive still stores
"Untitled" and the title bar may not follow the file name. Let NSDocument's
display-name sync own the title, and stamp the document title from the file
URL on save.
Confidence: medium.

### B10. `previewPNG` is written but never produced
Archives can carry `previews/preview.png`, decode reads it, and edits
invalidate it — but nothing ever renders a new one. After the first edit,
every save ships without a preview. Dead pipeline: either render one on save
(offscreen draw of `contentBounds`) or remove the entry from the format.
Confidence: high. Generating it also feeds QuickLook/thumbnails (delight).

### B11. Self-loop connectors are creatable and route oddly
Dragging the connector tool from an element back onto itself creates an
element→same-element connector; the orthogonal router and obstacle exclusion
both special-case connected IDs, so the result is a stub going nowhere.
Reject source == target on mouse-up (nudge: show a "no" cursor).
Confidence: high.

### B12. Escape does nothing
Esc does not cancel a connector drag, a move, a resize, or text editing, and
does not close a transient popover unless it is key. Standard expectation in
every drawing tool.
Confidence: high.

### B13. `selectAll` includes invisible parents' children inconsistently
`selectAll` filters `visible && editable`, but a *hidden* element's visible
child (parent hidden ≠ children hidden) is selectable while its container is
not — probably fine, but dragging such a selection does not move the hidden
parent, so the group visually tears. Clarify or document.
Confidence: low (needs a decision, not a fix).

### B14. Paste of duplicated elements stacks exactly on top
Copy → Paste → Paste places both copies at the visible center with zero
offset; the second paste is invisible. Add a small progressive paste offset
(or paste at the original position + step when the source rect already
occupies the drop point).
Confidence: high.

## 2. Performance

### P1. Every draw re-routes every connector (main stutter source)
`SceneRenderGeometry.connectorRoute` runs the full router (orthogonal =
visibility-grid Dijkstra over all elements as obstacles) per connector per
redraw. The persisted `resolvedRoute` cache is only ever written by archive
encode; the editing path never writes it back, and `translate`/`setFrame`
invalidate *all* routes on every mouse-move of a drag. Result: moving one
shape with 20 orthogonal connectors re-runs 20 Dijkstras per frame.
Fix: memoize routes in the editor controller keyed by element ID plus a
document generation counter (bump on every model change; selection-only
changes keep the cache). Draws during zoom/selection then cost nothing;
drags re-route only once per frame regardless of connector count.
Confidence: high. Largest single interactive-perf win.

### P2. `NSImage(data:)` decode per image per frame
`drawImage` decodes the PNG rendition from scratch on every draw call. Cache
`NSImage` by `displayAssetID` in the canvas view (invalidate on asset change /
memory warning).
Confidence: high. Second-largest perf win; turns scrolling with images from
a slideshow into scrolling.

### P3. No visible-rect culling
`drawElements` walks and draws every element regardless of `dirtyRect` /
`visibleModelRect`. Cull by frame (and route bounds for connectors) — cheap
and unblocks 1k-element canvases.
Confidence: high.

### P4. Per-frame attributed-string and path construction
`drawText` builds `NSAttributedString` + paragraph style every draw;
`shapePath`/`connectorPath` rebuild `NSBezierPath` every draw. Cache per
(element ID, style/content hash) or at least per generation. Only worth it
after P1–P3; measure first.
Confidence: medium.

### P5. Whole-document copy + validate per input event
`SceneEditor.apply` copies the document, applies, validates the *entire*
scene (including O(elements × depth) parent-cycle walk) and diffs it —
per `mouseDragged` and per keystroke. Fine at 100 elements, rough at 5k+.
Gesture updates could skip validation (validate at `endGesture`) or validate
incrementally. Selection-payload copies hash assets too.
Confidence: medium. Defer behind measurement; correctness risk low but
touches the editing core.

### P6. Save is a full synchronous encode + verify-decode on the main thread
`data(ofType:)` → canonical JSON, SVG export, Mermaid export, SHA-256 of
every entry (pure-Swift SHA-256, whole-file `[UInt8]` copy up front), ZIP
write, then a *full decode* to verify. With `autosavesInPlace` this runs on
every autosave tick. Mitigations: hash with CryptoKit on Apple platforms,
skip the verify-decode for autosave (keep for manual save), or move encode
off the main actor (NSDocument supports background `data(ofType:)` if state
is captured first).
Confidence: medium. Clearly heavy; the right cut needs profiling.

### P7. Stored ZIP + uncompressed JSON history
By spec, entries are STORED (no deflate). scene.json and up to 120 history
snapshots are highly compressible JSON. The spec accepts the trade
("deterministic, dependency-free recovery"); if file size matters, deflate
for non-asset entries is a format-v2 item.
Confidence: low (format decision, needs spec change).

### P8. Hit-testing re-routes connectors
`element(at:)` calls `connectorRoute` for every connector above the click
until a hit — same Dijkstra cost as P1 on *every click*. P1's cache fixes
this too.
Confidence: high (folds into P1).

## 3. Missing features (ranked by user impact)

### F1. Marquee (rubber-band) selection
Dragging empty canvas does nothing but deselect. Dragging should draw a
selection rect and select intersecting elements (option-toggle for
containment vs. intersection). The single most-missed canvas interaction.
Confidence: high. **Defer until PR #19 lands** (drag overhaul overlap).

### F2. Canvas settings UI: grid toggle, snap, canvas size, background
`SionCanvas` supports grid visibility/spacing/subdivisions, fixed vs.
infinite extent, and background color. Zero of it is reachable — the grid
renderer is dead code from a user's chair. Add a View-menu "Show Grid" +
a canvas inspector section.
Confidence: high. Small, self-contained.

### F3. Z-order commands
`SceneCommand.reorder` exists, is tested, and is never called. Bring to
Front / Send to Back / Forward / Backward (⌘⌥↑/↓ etc.) in an Arrange menu.
Confidence: high. Trivial to wire.

### F4. Duplicate (⌘D)
Copy+paste payload machinery already exists; duplicate = payload round-trip
in-process with a fixed offset. Also enables ⌘D-with-repeat "power duplicate"
later.
Confidence: high.

### F5. Group / Ungroup (⌘G / ⇧⌘G)
Model supports `parentID`, groups render nothing (by design), translate
cascades to descendants, validation prevents cycles. There is just no UI.
Add menu commands + editor methods (`setParent`), group frame = union of
children, ungroup preserves positions.
Confidence: high (mechanics exist; UI is the work).

### F6. Lock / Hide toggles
`lockState` and `visibility` are modelled, validated, respected by hit
testing and selection — and unreachable. Context menu + Arrange menu items;
inspector checkboxes.
Confidence: high.

### F7. Tool keyboard shortcuts
V select, R rectangle, T text, C connector, M magnets (OmniGraffle-like).
`keyDown` currently handles only Return/Tab/arrows/Delete.
Confidence: high. (Check PR #19's keyDown changes.)

### F8. Drag-to-create shapes at arbitrary size
Shape tool stamps a fixed 160×96 rect on click. Drag should define the frame
(shift = square, option = from center). Same for text frames.
Confidence: high. **PR #19 may cover part of this** ("persistent creation").

### F9. Click-click connector creation
Connector creation requires one continuous drag. Click source, move, click
target is the more forgiving interaction (and works better on trackpads).
Confidence: medium.

### F10. Snap to grid + smart alignment guides
No snapping at all. Grid snap first (cheap); element-to-element smart guides
with accent-colored lines and haptic ticks later (delightful).
Confidence: high for grid snap, medium for guides (needs candidate-edge
index; measure).

### F11. Text style controls
`TextStyle` (font family/weight/size, color, alignment, spacing, insets,
auto-sizing) has no editor UI at all. Inspector: font popup, size stepper,
alignment segment, color well.
Confidence: high (bigger UI surface; doable incrementally).

### F12. Image scaling/interpolation controls
`ImageScalingMode` (fit/fill/stretch/tile) and interpolation are modelled
and rendered; no UI. Inspector popup for image selection.
Confidence: high.

### F13. Copy as PNG / SVG (pasteboard export for other apps)
`copy` writes only the private selection type + plain text. Pasting a Sion
selection into Keynote yields "Rectangle\nEllipse". Render the selection to
PNG (and SVG) onto the pasteboard. Huge interop win; reuse the SVG exporter
and an offscreen render.
Confidence: high.

### F14. Export PNG / PDF / Print
Only SVG + Mermaid export exist. PNG at 1x/2x/3x, PDF via `NSView.dataWithPDF`,
and ⌘P printing. A diagramming tool without print surprises people.
Confidence: medium (PDF/print need pagination decisions for infinite canvas).

### F15. Drag & drop onto the canvas
The view registers no dragged types. Dropping an image file/PDF/SVG/Mermaid
file should insert at drop point. Paste path already has the machinery.
Confidence: high.

### F16. On-canvas connector label dragging + decoration editing
`labelPosition` and decorations are modelled; UI exposes neither. Dragging
the label along the route and an inspector section for arrowheads
(source/target: none/open/filled/circle/diamond) round out connectors.
Confidence: medium-high.

### F17. Manual connector waypoints
`ManualConnectorRoute` (orthogonal waypoints, curved/bezier control points)
is modelled, routed, translated, and persisted — with no editing gesture.
Drag a route segment to insert a waypoint; drag bezier handles.
Confidence: medium (interaction design needed). **[PR19: anchor editing may
overlap — re-check]**

### F18. Rotation UI [PR19], corner-radius editing, dash patterns
Rotation in PR #19. Corner radius: model has per-shape radius; no inspector
field. Dash patterns: modelled, rendered; no UI. Quick wins post-#19.
Confidence: high (radius/dash), n/a (rotation — PR19).

### F19. Zoom-to-selection, status bar zoom slider, ⌘scroll zoom, spacebar pan
Navigation affordances beyond menu zoom. Status bar also shows coordinates /
element count. **[PR19 adds zoom controls; extend, don't duplicate]**
Confidence: medium.

### F20. Alignment & distribution commands
Align left/center/right/top/middle/bottom, distribute horizontally/vertically
for multi-selections. Pure core geometry + menu items; very testable.
Confidence: high.

### F21. Stencil/shape library with previews
Current library palette is four text buttons. Shape gallery (all 8 kinds),
drag-out onto canvas, "save selection as stencil". Medium effort, big
perceived-value win.
Confidence: medium.

### F22. Accessibility tree for canvas elements
Canvas exposes a summary string only. Expose elements as AX children with
labels/frames so VoiceOver can navigate; announce connector topology.
Confidence: medium (AppKit AX for custom canvases is fiddly).

### F23. Mermaid import improvements
Import uses a fixed 3-column grid, ignores `direction`, subgraphs, arrow
types (`==>`, `-.->` render as plain arrows), and edge labels position.
A simple layered (Sugiyama-lite) layout would transform imported diagrams.
Confidence: medium (layout algorithm work in core; testable on Linux).

### F24. Element naming + layers/outline panel
`rename` command unused; no panel listing elements. An outline view doubles
as the missing group/visibility/lock UI (checkmark/eye columns).
Confidence: medium.

### F25. Text auto-sizing honored
`TextAutoSizing.fitHeight`/`fitWidthAndHeight` are modelled; canvas and
editor ignore them (frames stay fixed). Grow frames to fit text on commit.
Confidence: medium.

## 4. Visual / layout issues

### V1. Selection chrome ignores rotation [PR19-adjacent]
Selection rect and handles draw axis-aligned over rotated elements (see B1).

### V2. Fixed-size connector labels
Labels render in a hard 120×36 box regardless of content; long labels clip,
short ones get an oversized edit frame. Measure text and size the label box
per content (with a max).
Confidence: high.

### V3. Infinite canvas only grows within a session
`synchronizeCanvasBounds` unions monotonically; deleting/moving content
inward never shrinks the scrollable extent until reload. Recompute to content
bounds (with padding) when no gesture is active.
Confidence: medium (must not fight an active drag).

### V4. No hover feedback
No cursor changes per tool, no hover-highlight on connectable targets or
magnets, no resize cursor over handles. Makes the app feel inert.
Confidence: high (small, high-polish).

### V5. Selection handles are squares at 4.5 pt
Tiny and dated; OmniGraffle-style circles at ~7 pt with a white ring read
better, and need a zoom-aware constant screen size (currently model units —
handles shrink/grow with zoom).
Confidence: medium.

### V6. Connector preview has no target highlight
While connecting, the would-be target element doesn't highlight and the
snap magnet doesn't pulse. Cheap draw pass, big confidence cue.
Confidence: high.

### V7. Default canvas color is a fixed light gray in dark mode too
`SionColor.canvas` is static. Fine for print fidelity, but the fixed-canvas
"page" look could adapt subtly. Low priority.
Confidence: low.

### V8. Toolbar is sparse
Five tool segments + two palette buttons. No fill/stroke quick controls, no
zoom readout. **[PR19 adds zoom controls.]**
Confidence: n/a (design pass).

### V9. History palette rows are bare buttons
No thumbnails (preview pipeline is dead, B10), no relative timestamps, no
current-revision marker. Render 64-pt thumbnails from retained scenes.
Confidence: medium (depends on B10).

## 5. Aesthetics & delight (novel ideas)

### D1. Connector crossing hops
Orthogonal routes that cross unrelated connectors get tiny jump arcs —
instantly "pro diagramming tool". Pure renderer addition over route
polylines; needs crossing detection between routes.
Confidence: medium (perf cost to compute crossings; cache with P1).

### D2. Sketch / hand-drawn stroke style
A `handDrawn` style flag rendering strokes with deterministic jitter (seeded
by element ID so it's stable per element and export-stable). Charming for
wireframes; SVG exporter can reproduce with the same seed.
Confidence: medium-high (renderer + one model field; format-additive).

### D3. Tidy / auto-layout command
"Arrange → Tidy Diagram" runs layered layout over the connector graph.
Turns pasted Mermaid into a presentable diagram in one click; pairs with F23.
Confidence: medium.

### D4. Smart guides with haptics
Snap lines + `NSHapticFeedbackManager` tick on snap. Small code, big feel.
Confidence: medium (depends on F10).

### D5. Minimap
Floating overview in a corner for large canvases; click/drag to navigate.
Feeds off the same render cache. Moderate effort, high cool factor.
Confidence: medium.

### D6. Command palette (⌘K)
Fuzzy "insert shape / toggle grid / export" launcher. Reuses existing
actions; very demo-able.
Confidence: medium.

### D7. Presentation mode (⌥⌘P)
Full-screen, hides chrome, arrow keys step through "scenes" (saved
viewports). A new use-case, not just polish.
Confidence: low-medium (needs scene bookmarks model).

### D8. Spring-loaded paste: paste-drag
Hold after ⌘V to position the pasted copy before committing. Quirky, feels
great, small state machine.
Confidence: medium.

### D9. Power-duplicate (repeat ⌘D repeats the last offset)
After a manual move of a duplicate, ⌘D repeats move+duplicate — classic
Delightful™ for building grids/rows.
Confidence: high (builds on F4).

### D10. ASCII-art paste
Paste a box-drawing/ASCII diagram, get native shapes + connectors. Quirky
signature feature; parser is pure core and testable on Linux.
Confidence: medium.

### D11. Animated zoom & gentle spring on selection
`NSAnimationContext` zoom transitions; selection handles pop with a subtle
scale animation. Cheap polish.
Confidence: medium.

### D12. QuickLook extension + Finder thumbnails
Generate from `previews/preview.png` once B10 is fixed.
Confidence: medium (packaging work).

## 6. Suggested implementation order (next actions)

1. **P1 route cache** — biggest felt-perf win; mostly SionEditorController +
   a small SionCore cache type (Linux-testable).
2. **P2 image cache + P3 culling** — one canvas perf PR.
3. **B5+B4 grid density/subdivisions** — small renderer fix.
4. **B6 hide text under editor; B11 self-loop; B12 Esc; B14 paste offset** —
   small canvas/editor fixes (batch as separate micro-PRs or one "canvas
   interaction fixes" PR; keep each commit atomic).
5. **F3 z-order + F20 align/distribute + F4 duplicate + D9** — Arrange menu,
   mostly core geometry + editor methods (Linux-testable).
6. **F2 grid toggle / canvas settings** — menu + inspector section.
7. **F5 group/ungroup + F6 lock/hide** — commands exist; UI wiring.
8. **B2 SVG text wrap** — core export fidelity with heuristic metrics.
9. **F13 copy as PNG/SVG** — interop.
10. Post-#19: marquee (F1), hover feedback (V4/V6), handles (V5), drag-to-
    create (F8), rotation-aware hit testing (B1).

Explicitly deferred: P5–P7 (measure/spec first), F17 manual routes (design),
F23/D3 layout engine (own milestone), D5–D7 (larger surfaces).
